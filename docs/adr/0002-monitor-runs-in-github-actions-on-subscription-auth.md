# The monitor runs in GitHub Actions, authenticated by a Claude subscription token

The weekly monitor runs as `anthropics/claude-code-action@v1` on a `schedule` cron in this
repository, invoking a skill committed under `.claude/skills/`. It authenticates with
`CLAUDE_CODE_OAUTH_TOKEN` — generated by `claude setup-token`, which requires a Claude
subscription — rather than an `ANTHROPIC_API_KEY`.

## Considered options

**An Anthropic-hosted routine** was the closest fit to what we wanted: cloud-run, no API
key, and able to use skills committed to the cloned repository. We rejected it on three
counts. Routines "belong to your individual claude.ai account… not shared with teammates",
which reproduces the failure that killed the previous OpenClaw digest — when the owner's
account goes, so does the digest, and nobody else can see or revive it. Routines clone the
default branch each run and push to `claude/`-prefixed branches, so the monitor's state file
would land somewhere the next run never reads. And the default cloud environment allowlists
only package registries and common development domains, so CDC, openFDA and NCBI would need
a Custom environment configured through a web form rather than in this repo.

**A desktop scheduled task** has the same single-point-of-failure problem, with a laptop as
the server.

**GitHub Actions with an `ANTHROPIC_API_KEY`** works identically but bills per run instead of
drawing on an existing subscription.

## Consequences

The token belongs to one person's subscription, so runs draw on that person's plan and the
workflow stops when the token is revoked or the subscription lapses. That is deliberately
*less* fragile than it sounds: unlike a routine, everything except the token — workflow,
skill, prompt, source adapters, state — lives in this repo, so a successor regenerates a
token with `claude setup-token`, replaces the secret, and the monitor resumes. Failure is
also visible, surfacing as a red scheduled run rather than silence.

`claude setup-token` produces a long-lived but not permanent credential; expect to
regenerate the secret periodically.
